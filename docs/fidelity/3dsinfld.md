# 3DSINFLD — the 3D sinus field (COMAN)

Sources: `COMAN/MAIN.C` (228 lines) over `COMAN/ASM.ASM` (238: `inittwk`, `docol`, `docopy`,
`setpalarea`) and `COMAN/THELOOP.INC` (5,230, generated by `COMAN/DOLOOP.C`); assets
`W1DTA.BIN`/`W2DTA.BIN` (65,536 bytes each). Port: `bins/secondreality/src/parts/coman.rs`
(`"3dsinfld"`, not a Rust identifier, hence the module name); its module doc has the chain-4-off
screen, init, `doit`, the tick model, the unlinked background and the preserved bugs. Run: no boot
anchor; the mapping is stated per keyframe (§6). Music: `MUSIC1` seeked to order 91 (derived),
pre-roll 527 polls (D31).

## 1. Timeline

One tick is one vblank; one render iteration is two (`frame += (frepeat = dis_waitb())`,
`MAIN.C:105`, `:111`).

## 2. Init: the palette and the linked tables

The palette formula (`MAIN.C:127-164`) walks entries **223 down to 8**; the `*9/6` pass brightens
entries 0..239 and clamps at 63; the dark-red bar writes 255 down to 232; entry 0 is forced black;
the last loop overwrites 240..255 from `combg`. The pins
(`the_palette_is_the_formula_with_the_bar_and_the_unreachable_overrun`):

| entry | source `a` | value (6-bit) |
|---|---|---|
| 0 | — | `(0, 0, 0)`, forced black |
| 8 | 255 | `(1, 0, 0)` |
| 37 | 220 | `(19, 0, 16)`, the red diamond's peak |
| 100 | 146 | `(0, 27, 54)` |
| 223 | 0 | `(0, 63, 63)` |
| 232..239 | 23..16 | the dark-red bar, `((a-4)/2, 0, 0)` |
| 240..255 | — | the `combg` overrun |

The same test's exhaustive `i16` colour sweep reaches 127 and no more, so DAC 240..255 never reaches
the screen. `SIN1024.INC` is the tree's common copy, `parts::sin1024::SIN1024`
(`sin1024::tests::the_table_is_the_sources_1024_words`; asset-inventory §B.7 gives the md5 identity).

**The unlinked background.** `COMAN/MAKEFILE:16-17` links `main.obj asm.obj theloop.obj
..\dis\disc.obj` plus the four wave-table objects; `asm.obj` holds `_combguse` (a `90*160 dup(0)`
BSS array) and no `combg` data, and `MAKEFILE:6`'s `asm_f` defines no `PXLSUX`
(`ASM.ASM:143`), so `docopy`'s background half is not assembled. `combg` is `char combg[16]`
(`MAIN.C:8`): the palette loop reads `combg[736..783]` and the `combguse` fill (`MAIN.C:166-176`)
up to `combg[29582]` (`x = 79, y = 89`). The port keeps the 16-byte array, reads the palette at the
source's indices (all past the array, giving zero) and draws no background; `docopy`'s test asserts
rows 0..51, where the `PXLSUX` half wrote, stay zero.

**The wave tables.** `CALCW12` is off (`MAIN.C:6`), so `MAIN.C:212-213` takes the linked tables.
Each is 32,768 signed little-endian words, `W1DTA` **−33..41** and `W2DTA` **−56..63**
(`the_wave_tables_are_the_linked_sixty_four_kilobyte_ints`). The generator half (`MAIN.C:179-210`)
is dead and not ported.

## 3. The tick model

`dis_waitb`'s INDEMO arm (`DIS/DISINT.ASM:158-183`) waits for `copperframecount` to move and
returns the count since the last call. One render costs two (the reference's picture changes every
second boot frame, `reference-indices.md` §16.3), so the inner `while(frepeat--)` body runs twice an
iteration. At `frame == 4` both bodies call `dis_waitb(); setpalarea(...)` (`MAIN.C:69-72`) and
each spends a vblank, so that iteration takes four ticks while `frame` still advances two: the
iteration ticks are `0, 2, 4, 8, 10, …`
(`the_iterations_run_every_second_tick_and_the_frame_four_waits_add_two`). The upload re-sends the
palette in force (same bytes); the wait it spends is what is visible.

`flip` shows one page and copies into the other, so picture k is first displayed two vblanks after
it was drawn (`the_two_pages_alternate_and_the_display_lags_one_iteration`).

`xw`/`yw` are copied **before** the column loop (`MAIN.C:84`) and `xwav`/`ywav` change at
`a == 80` for the next frame. Updating them mid-loop matches the reference's left half only; the
15500 comparison pins the source's order (the right half's curvature is the difference).

The `frame < 4444` cap (`MAIN.C:57`) is never reached: the music break ends the part
(`the_part_ends_on_the_music_break_not_the_dead_frame_cap`).

## 4. The ray march, checked against the shipped program

`theloop` (in `coman.rs`) translates `THELOOP.INC` instruction for instruction; its item docs cover
the swapped 16.16 state and the two carries (`add eax; adc ax,0`, and `_@seek1a`'s `adc` carrying
the compare's CF past a taken signed `jge`, which `DOLOOP.C:141`'s "carry=0 when jmp here!" gets
wrong).

- `the_ray_march_matches_the_shipped_generated_program` parses the 5,230-line `THELOOP.INC` into
  its ~24 instruction forms, executes it with registers and flags, and compares the whole 64 KB vbuf
  against `theloop` for five columns (including the first, at `rot2 = 4`).
- `the_zwave_is_the_generators_three_sines_at_the_labels_it_emits` reads all 128 emitted `add bx,<k>`
  constants (`zwave[j] - 240`, `zwave[j] = (int)(16.0*sin(j*2*pi*3/192))`) from the file.
- `docopy_doubles_each_column_and_starts_below_its_eighteen_row_clear` pins the `(a, a, b, b)`
  doubling, the 18-row clear whose `rep stosd` moves the copy to row 70, and the vbuf clear of rows
  68..97 (`ASM.ASM:216-229`); `docopy_shifts_by_one_row_a_startrise_unit` pins one row a unit.

## 5. The music: the derived order, the pre-roll, the gate and the end

Two filed traces cross the part's start:

```text
$ awk -F, '$2!=p {print; p=$2}' reference/music/second3d/trace.csv | head -3
frame,ord,row,pat,loop,speed,tempo,zinfo,zplus,zframe
15000,91,59,37,0,6,130,0,1,6884
15038,93,0,68,0,6,130,0,2,6912
$ awk -F, '$2!=p {print; p=$2}' reference/music/second3b/trace.csv | tail -1
15031,93,0,68,0,6,130,0,2,6911
```

Order 92 is the `254` marker. The window `(15000, 15100]` (`reference-indices.md` §16) spans the
91→93 crossing and the part marks no start frame, so order **91 is derived, not measured**: the order
in force where the window opens.

`init` pre-polls **527** frames (`Coman::MUSIC_PRE_ROLL`): the 527th leaves the published row at 63
with `musplus == -1`, and the first tick's poll reads order 93 row 0, `musplus == 0`, which passes
`MAIN.C:56`'s gate (`the_entry_pre_roll_lands_the_gate_on_order_93_row_zero`). Tick 0 is therefore
the order-93 crossing the traces put at 15031–15038. A mid-chain start polls nothing
(`a_mid_chain_start_does_not_pre_poll_and_blacks_the_inherited_screen`; part-sequence.md (block
seams / pre-roll / mapping conventions)).

The part ends on `MAIN.C:59-60`'s break in MUSIC1 order 96's `zplus == 1` tail: row 57 first
publishes `musplus == -7`, read at **tick 2,014**. In that tail `startrise` rises a vblank, and once
it reaches 130 the copy's first row `70 + startrise` is row 200: the screen is flat black, the
reference's 17000 (`the_terrain_rises_off_the_bottom_before_the_break`). The part draws off-screen
for about fifty more ticks.

## 6. The mapping and the comparison

All four keyframes are **RGB only**: the part writes CRTC `0x0C` every frame, and the oracle's
indexed read of the `0x80` offset is racy, so no `.idx` is filed (`reference-indices.md` §16.2;
`tests/coman.rs` asserts the files do not exist).

| keyframe | rendered ticks | implied origin (boot − tick) | differing | register |
|---|---|---|---|---|
| 15500 | 464, 465 | 15036 | 0 px, max delta 0 | exact |
| 16000 | 966, 967 | 15034 | 0 | exact |
| 16500 | 1470, 1471 | 15030 | 0 | exact |
| 16800 | 1772, 1773 | 15028 | 0 | exact |

The counts are the `3dsinfld` rows of `xtask/src/rediff/table.rs` (first tick of each pair).
Each keyframe is drawn on two consecutive ticks, so `tests/coman.rs` compares both and asserts that
the tick before and the tick two after differ: the reference's two-frame step
(`reference-indices.md` §16.3), D19's support made from the rendered side.

**The mapping drifts, and it is a mapping, not an anchor.** The ticks between keyframes are 502, 504
and 302 for 500, 500 and 300 boot frames, so the implied origin moves 2, 4 and 2 frames: the
reference renders about 1.99 frames an iteration (its `dis_waitb` occasionally returns one) and the
port's model is a fixed two. The origins are stated per keyframe; the timing difference is A26.
The run's manifest says `index_origin: "part"`, `anchor: null`
(`the_run_is_numbered_in_its_own_frames_and_declares_the_derived_music_row`).

## 7. Decisions and preserved behaviour

- **Fixed two vblanks a render** against the reference's ~1.99 (A26, §6).
- **No background**: the `combg` overrun and the unassembled `PXLSUX` half (§2).
- **`cameralevel` is dead**: `MAIN.C:54` writes -270, `docol` loads it into `ax`, `THELOOP.INC`
  stores it in `theloop_heigth`, and nothing reads it.
- **Dead or unobservable**: the frame-4 re-upload (§3), the `frame < 4444` cap (§3), the
  `CALCW12` generator (§2).
- `docopy`'s fixed bands and `docol`'s `~1` mask on all four coordinates are `bugs.md` §20.
